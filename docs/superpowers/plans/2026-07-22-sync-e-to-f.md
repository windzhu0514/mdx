# Mora E-to-F Workspace Synchronization Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bring `F:\WorkspaceIdea\mdx` to the complete feature, security, test, documentation, and build baseline of `E:\WorkspaceGo\mdx` without losing F's existing Markdown import and YAML front matter behavior.

**Architecture:** Treat E as the authoritative baseline for all shared source paths. Exclude generated and repository-local directories from the copy, then restore Markdown import as an isolated Rust module and a public Tauri command before wiring the existing Vue file menu to it. Verify source parity by SHA-256 hashes and verify behavior through frontend, Rust, and packaged Tauri builds.

**Tech Stack:** Vue 3, TypeScript, Vite, Vitest, Toast UI Editor, Tauri 2, Rust

## Global Constraints

- Preserve the custom ZIP-based MDXNote format; do not introduce Web MDX or JSX semantics.
- Preserve `.tmp + .bak` safe-save behavior and all archive validation limits.
- Do not copy `.git`, `node_modules`, `dist`, or `src-tauri/target`.
- Do not remove F's `import_markdown` behavior or YAML front matter parsing.
- Use only public Toast UI, Vue, and Tauri APIs; do not add DOM timing patches.
