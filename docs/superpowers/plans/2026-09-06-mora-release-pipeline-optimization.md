# Mora Release Pipeline Optimization Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在普通提交阶段提前发现通用回归，并将四平台发布改为并行构建、完整性校验后单点创建 Draft Release。

**Architecture:** Ubuntu 日常 CI 和发布 `verify` 负责质量门禁；发布矩阵只构建并上传 Actions Artifact，不写 GitHub Release。单一 `release` Job 下载全部产物，通过无第三方依赖的 Node 汇总器验证和生成 `latest.json`，然后创建或安全复用同标签 Draft 并上传资产。

**Tech Stack:** GitHub Actions、Tauri 2、`tauri-apps/tauri-action`、Node.js 22 内置测试框架、Vitest、GitHub CLI

**Spec:** `docs/superpowers/specs/2026-09-06-mora-release-pipeline-optimization-design.md`

## Global Constraints

- 保持 Windows x64、macOS Apple Silicon、macOS Intel 和 Linux x64 四个现有目标及 bundles 不变。
- 保持 Tauri updater 私钥、公钥和签名格式不变，不输出任何 Secret。
- 平台矩阵不得创建或修改 GitHub Release，也不得各自上传 `latest.json`。
- 只有完整资产集才能进入单一 Draft Release；不自动公开 Release，不自动创建或推送标签。
- 不修改或重发 `app-v0.1.2`。
- 不引入 npm 依赖、外部服务、发布数据库或通用插件抽象。
- 保留用户现有未提交 `TODO.md`，不得格式化、暂存或覆盖。
