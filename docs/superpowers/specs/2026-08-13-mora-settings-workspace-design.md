# Mora 完整设置工作区设计

## 背景

当前偏好设置使用居中的模态面板和全屏遮罩。用户调整主题、字体、字号、行高或阅读宽度时，遮罩会盖住编辑器，无法同时观察排版效果。随着图片、快捷键及更多编辑器配置加入，现有窄面板也不适合承载长期增长的设置项。

本次将偏好设置改造成应用内的完整设置工作区，并为外观设置提供固定示例的实时预览。这是面向最终用户的正式设置体验，不是开发调试工具。

## 已确认目标

- 设置工作区替换当前三栏内容区，不再显示模态遮罩或覆盖正文。
- 标题栏、主菜单和底部状态栏继续保留。
- 设置采用左侧分类导航和右侧内容区域。
- 外观页使用“配置区 + 实时预览区”布局。
- 返回编辑器后保留当前文档、编辑器实例、选区、撤销历史和滚动状态。
- 设置沿用现有即时应用和自动保存行为。
- 首期分类为“外观”“编辑器”“AI”。
- 暂不增加设置搜索；配置规模明显增长时再加入。

## 不采用的方案

### 可拖动浮窗

浮窗仍会遮挡正文，还需要处理拖动边界、窗口缩放、位置记忆和键盘焦点。它适合临时工具，不适合作为持续扩展的完整设置入口。

### 360–400 px 右侧栏

右侧栏适合少量快捷外观选项，但无法舒适展示说明文字、路径选择、AI 配置以及未来更复杂的设置。较窄窗口下还会明显压缩编辑区。

### 独立系统窗口

独立窗口可以移动到第二屏，但会引入 Tauri 多窗口生命周期、状态同步和焦点管理。本次需求用单窗口工作区即可满足，无需增加这些复杂度。

## 信息架构

设置工作区由两部分组成：

1. 左侧分类导航。
2. 当前分类的主内容区。

首期分类及设置归属：

### 外观

- 主题
- 字体
- 代码字体
- 字号
- 行高
- 实时排版预览

### 编辑器

- 阅读宽度
- 默认显示文档目录

### AI

- OpenAI-compatible Base URL
- 模型
- API Key 保存、替换和删除

分类导航顶部提供“返回编辑器”。不增加单独的保存、应用或取消按钮；所有变更继续即时保存。

## 工作区切换

`App.vue` 继续使用现有 `showSettings` 状态，不引入路由或第二套全局导航状态。

- 编辑器三栏工作区使用显示/隐藏切换，打开设置时保持挂载。
- 设置工作区只占据原 `.main-body` 对应的内容空间。
- 打开设置时隐藏工作区侧栏、编辑区和文档目录，但不卸载 `MoraEditor`。
- 返回编辑器时重新显示原三栏，不创建新的编辑器实例，不重新装载文档。
- 设置模式下隐藏顶部的编辑模式切换按钮，避免用户误以为它会作用于设置页。
- 菜单、窗口控制和状态栏保持可用。

这种切换方式保留 Milkdown/CodeMirror 的实例状态，不读取编辑器内部 DOM，也不复制 Markdown 正文。

## 组件边界

现有 `SettingsPanel.vue` 改名为 `SettingsWorkspace.vue`，职责从模态对话框调整为设置工作区：

- 渲染分类导航。
- 管理当前选中的设置分类，默认打开“外观”。
- 渲染现有偏好字段并继续发出 `update`、`save-ai-key`、`delete-ai-key` 和 `close` 事件。
- 渲染外观页的静态实时预览。

`App.vue` 仍负责：

- 打开和关闭设置工作区。
- 持有并保存偏好状态。
- 执行 API Key 的系统存储操作。
- 保持编辑器工作区挂载。

不增加设置仓库、路由、适配层或第二套偏好状态。删除 `SettingsWorkspace` 会直接导致设置 UI 不存在；除此之外没有新增模块。

## 实时预览

实时预览使用固定的语义化 HTML 示例，不引入新的 Markdown renderer，也不读取当前文档正文。它不是第四种编辑器视图，不参与 `.mdx` 数据流。

示例内容包含：

- 一级标题和二级标题。
- 中英文混排正文。
- 粗体、斜体和链接。
- 行内代码。
- 多行代码块。
- 足够长的段落，用于观察字号、行高和可读性。

预览直接使用现有 CSS 变量：

- `--editor-font-family`
- `--editor-code-font-family`
- `--editor-font-size`
- `--editor-line-height`
- 当前主题的背景色、正文色、弱化色、边框色和强调色

因此主题和外观偏好变化会立即反映在预览中，不需要组件内部复制偏好值。

阅读宽度属于“编辑器”分类。首期不在固定预览中模拟真实文档宽度，避免窄窗口中形成双重横向约束；返回编辑器后可查看它对当前文档的效果。

## 布局与响应式行为

桌面宽窗口下：

- 分类导航宽约 `220 px`。
- 外观配置区宽约 `420–520 px`。
- 实时预览区使用剩余空间，并设置合理最小宽度。
- 内容整体限制最大宽度并居中，避免超宽屏上的表单跨度过大。

中小窗口下：

- 左侧分类导航继续保留。
- 配置区和实时预览区改为纵向排列。
- 主内容区和分类导航分别保持可读的最小宽度。
- 设置内容区域独立滚动，应用标题栏和状态栏不随内容滚动。

不提供用户拖拽调整设置列宽；只有出现明确的可用性问题时再考虑可调分栏。

## 交互与可访问性

- 设置根节点使用命名明确的区域语义，不再使用 `role="dialog"` 或 `aria-modal="true"`。
- 分类导航使用可识别的导航语义，并标记当前分类。
- 打开设置时将焦点移到设置工作区标题或返回按钮。
- 返回编辑器后恢复到合理的可见焦点目标，不操作编辑器内部 DOM。
- 分类和所有字段均可用键盘完成操作。
- 点击设置工作区外部不会自动关闭。
- 只通过“返回编辑器”按钮或已有设置菜单动作退出设置工作区。
- API Key 状态、禁用规则和保存逻辑保持现状。

## 数据流和错误处理

所有设置继续通过现有 `updatePreferences` 数据流即时规范化、持久化并写入 CSS 变量。设置工作区不保留第二份偏好副本。

API Key 操作继续使用现有异步状态和错误反馈。工作区改造不改变凭据的存储位置、传输方式或错误处理。

若偏好存储包含旧值，继续由现有 `normalizePreferences` 迁移和回退；本次不修改存储键或数据格式。

## 测试与验收

### 组件测试

- 默认显示“外观”，并可切换“编辑器”和“AI”。
- 每个字段只出现在其所属分类。
- 字体等外观字段继续发出正确的偏好补丁。
- 实时预览包含中英文、行内代码和代码块。
- 根节点不再具有模态对话框语义。
- 返回按钮发出关闭事件。

### App 集成测试

- 打开设置时设置工作区可见，编辑器三栏不可见但 `MoraEditor` 未卸载。
- 返回编辑器后仍是同一个文档和编辑器实例。
- 设置期间修改偏好后，返回编辑器仍使用新值。
- 设置模式下编辑模式切换控件不可见。

### 样式测试

- 宽窗口使用导航、配置和预览布局。
- 中小窗口下配置与预览纵向排列。
- 不再存在设置遮罩和模态面板样式依赖。
- 实时预览使用正文和代码字体变量。

### 手动验收

- 打开一个含有编辑历史的文档，进入设置，调整主题、字体、代码字体、字号和行高。
- 确认预览立即变化。
- 返回编辑器，确认当前文档、选区、撤销历史和滚动位置未丢失。
- 调整窗口宽度，确认设置内容无横向溢出，预览按断点移动到配置区下方。

## 当前必须实现

- 完整设置工作区与三类导航。
- 外观页实时静态预览。
- 编辑器工作区保持挂载的切换方式。
- 响应式布局和键盘可访问性。
- 现有偏好与 AI 设置能力迁移。

## 仅在指标不达标时增加

- 设置搜索：分类或设置数量增长到难以快速定位时增加。
- 可调列宽：用户测试显示固定布局不能覆盖常见窗口宽度时增加。
- 分类深层导航：单个分类内容明显超过一屏且难以扫描时增加。

## 本次不实现

- 可拖动设置浮窗。
- 独立 Tauri 设置窗口。
- 设置路由系统。
- 当前文档内容预览。
- 新的 Markdown 预览器或第二份正文状态。
- 设置导入、导出或云同步。

## 删减检查

- 复用现有 `showSettings`，不新增全局模式管理器。
- 复用现有偏好状态和更新事件，不新增 store。
- 只将现有设置组件调整为匹配新职责的工作区组件，不拆分额外表单子组件。
- 预览使用静态 HTML 和现有 CSS 变量，不新增渲染依赖。
- 不提前实现搜索、拖拽分栏或多窗口同步。

该方案以最少的新结构满足“长期可扩展的完整设置”和“外观调整实时可见”两个已确认目标。
