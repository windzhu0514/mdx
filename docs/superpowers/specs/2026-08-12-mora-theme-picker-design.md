# Mora 六主题选择设计

## 目标

为 Mora 增加宣白、墨黑、黛蓝、松青、绛红、藤紫六套完整界面主题，并让用户通过菜单打开位于窗口底部的主题选择条，横向浏览、即时切换并随时关闭。

## 当前必须实现

- 在“视图”菜单增加“选择主题...”入口。
- 点击入口后，在状态栏上方显示停靠于窗口底部的主题选择条；选择条占用布局空间，不覆盖正文。
- 选择条包含标题、右上角关闭按钮和可横向滚动的六张主题预览卡片。
- 卡片同时预览窗口栏、侧栏、正文背景、正文文字和强调色；当前主题显示明确选中状态。
- 点击卡片立即更新整窗主题，并沿用现有偏好存储自动持久化。
- 保留“跟随系统”能力；它继续位于偏好设置中。打开选择条时，用当前解析后的六主题之一标记选中状态。
- 旧偏好值 `light`、`dark`、`monochrome` 必须兼容迁移，避免已有用户启动失败。
- 墨黑和黛蓝按深色主题同步给 Tauri 原生窗口及 Mermaid；其余四套按浅色主题处理。
- 主题选择条使用按钮和单选组语义，支持键盘焦点，关闭按钮具有明确可访问名称。

## 最小结构

- `src/composables/usePreferences.ts`：继续作为主题标识、元数据、明暗判断、偏好规范化和持久化的唯一状态入口，不新增主题注册系统。
- `src/components/ThemePicker.vue`：只负责底部选择条的呈现和 `select`、`close` 事件，不拥有第二份主题状态。
- `src/App.vue`：只拥有选择条开关，将 `resolvedTheme` 传给组件，并把选择事件转给现有 `updatePreferences`。
- `src/experience.css`：定义六套完整颜色变量以及选择条布局；主题卡片与整窗主题使用同一组变量定义。

## 交互

1. 用户打开“视图 > 选择主题...”，菜单关闭，底部选择条出现。
2. 用户横向滚动卡片列表比较六套主题。
3. 用户点击某张卡片，整窗立即切换、卡片选中状态同步、偏好立即保存；选择条保持打开，便于继续比较。
4. 用户点击选择条右上角关闭按钮，选择条消失，主题保持不变。

## 本次不实现

- 自定义配色、主题编辑器或导入导出。
- 主题收藏、排序、搜索或额外预览窗口。
- 鼠标悬停即切换主题。

## 主题舒适度统一

- 墨黑保持现有配色不变。
- 编辑器画布、Milkdown 和 CodeMirror 在六套主题中统一使用窗口基础底色，避免正文形成与窗口割裂的独立色块。
- 宣白、松青、绛红、藤紫的顶部栏、编辑区、左侧工作区、右侧目录及侧栏标题统一使用各自的基础底色，不再用大面积明度或色相差区分区域；区域层级只通过现有边框、文字和选中态表达。
- 宣白使用中性柔白，不引入黄色纸张倾向；松青、绛红、藤紫使用低彩度背景和近中性正文文字。主题色集中用于选中态、焦点和强调。
- 弹窗、菜单、输入框和卡片继续使用表面色或浮层色，保证可交互控件仍有必要的层级，不属于整窗主背景统一范围。
- 黛蓝保留深色蓝调，但降低大面积背景的蓝色饱和度，并采用与墨黑一致的明度层级节奏。
- 各主题统一使用“基础底色 < 导航表面 < 弹出表面”的层级关系，以及相近强度的边框、阴影、悬停和弱强调状态。

## 验收

- 菜单入口可打开选择条，关闭按钮可关闭。
- 六张卡片名称、顺序和预览均正确，并可横向滚动。
- 每张卡片点击后 `document.documentElement.dataset.theme`、本地偏好和选中状态立即一致。
- 重启加载已保存主题；旧主题值可迁移。
- 深色原生窗口和 Mermaid 判断覆盖墨黑、黛蓝。
- 组件测试、偏好测试、应用集成测试、主题 CSS 测试及仓库规定的三项构建全部通过。
