# Mora Word 与 PDF 直接导出设计

## 目标

为当前活动文档增加真实 `.docx` 和 `.pdf` 文件导出。导出必须使用编辑器内存中的最新规范 Markdown，不要求先保存 `.mdx`，并保留现有 Markdown 导出与系统打印能力。

## 用户交互

“文件”菜单按以下顺序提供：

- 导出 Markdown...
- 导出 Word...
- 导出 PDF...
- 打印...

Word 和 PDF 操作先打开系统保存对话框，默认文件名取当前文档名，分别使用 `.docx` 和 `.pdf`。用户取消保存时静默结束；生成成功时状态栏显示明确结果；失败时显示具体原因。打印继续使用现有 WebView 打印对话框。

导出不改变活动文档、编辑模式、脏状态、磁盘路径或正文，也不要求用户先保存未命名文档。

## 内容范围

首版必须支持：

- 文档标题和普通段落
- 一级至六级标题
- 粗体、斜体、删除线、行内代码和链接
- 有序列表、无序列表和任务列表
- 引用、代码块、分割线和显式换行
- GFM 表格
- `assets/...` 图片
- Mermaid 代码块生成的图表
- `attachments/...` 附件以带文件名的文本引用表示

Word 和 PDF 使用 A4 纵向页面、约 25 mm 页边距、中文友好的字体回退、稳定的标题层级和段落间距。PDF 文本必须可搜索和复制，不能把整页栅格化。图片等比缩放到正文宽度以内；Mermaid 以中性浅色主题渲染到白色背景，避免当前应用深色主题污染纸面输出。

首版不实现目录字段、批注、修订、脚注、附件二进制嵌入、PDF/A 或 PDF/UA。这些能力不是“Word/PDF 导出”的必要条件，删除后不影响本次验收。

## 架构

### 前端导出编排

`App.vue` 负责保存路径、状态和错误反馈。新增小型导出辅助模块负责组装请求：

1. 读取活动文档的规范 Markdown、标题和资源会话。
2. 等待现有 Milkdown/Mermaid 预览完成。
3. 从现有 Mermaid 预览链取得按正文顺序排列的源码，以中性主题重新渲染并转换为 PNG。
4. 将 Markdown、所有已加载资源和 Mermaid PNG 一次性发送给 Tauri。

`ResourceSession` 新增只读的 `exportResources()`，返回当前会话中的全部资源；现有 `newResources()` 仍只服务 `.mdx` 保存。该能力不可由现有方法替代，因为已保存并重新打开的图片不是“新资源”，但仍必须进入导出文件。

`MoraEditorHandle` 新增只读的 `getMermaidDiagrams()`。它复用 Milkdown 的 ProseMirror 文档顺序和当前 Mermaid 预览数据，不扫描或修改编辑器内部 DOM，也不创建第二份正文状态。

### 公共文档模型

Tauri 新增 `document_export` 模块和一个 `ExportDocumentRequest`：

- `destination_path`
- `title`
- `markdown`
- `resources`
- `mermaid_diagrams`
- `format`，取值为 `docx` 或 `pdf`

后端使用 Markdown 解析器把正文转换为最小公共块模型，再由两个输出器消费。公共模型只包含本次范围需要的块和行内样式；它存在的理由是让 DOCX 与 PDF 对同一 Markdown 得到一致结构。若删除它，两个输出器必须分别解析 Markdown，容易产生列表、表格和资源处理差异。

资源按规范相对路径匹配。Base64 解码、格式识别和尺寸检查集中在公共层；未找到的图片输出可读占位文本而不是终止整个导出；非法 Base64 或不受支持的图片格式返回明确错误。Mermaid 通过正文中的出现顺序与请求中的 PNG 对应；渲染失败的图表退化为带语言标记的代码块。

### DOCX 输出

使用 `docx-rs` 生成真正的 OOXML ZIP 包：

- Word 样式承载正文、标题、引用和代码样式。
- Word 编号定义承载有序、无序和任务列表，不用手写项目符号字符。
- Word 表格承载 GFM 表格并设置明确列宽、表头和单元格边距。
- 图片和 Mermaid PNG 写入 media 关系并按可用宽度等比缩放。
- 文档属性写入标题；所有中文文本保持 Unicode。

### PDF 输出

使用 `typst-as-lib` 在进程内把公共模型生成的 Typst 源码编译为 PDF：

- 不调用外部 CLI、浏览器打印或 LibreOffice。
- 通过静态文件解析器提供图片和 Mermaid PNG。
- 通过系统字体搜索选择可覆盖中文的字体；若没有合适字体，导出失败并提示缺少中文字体，而不是生成方框字。
- 编译结果直接写入用户选择的目标路径，文本保持可搜索和复制。

Typst 仅作为 PDF 排版引擎，不成为新的编辑器正文格式，也不会写入 `.mdx`。

### 安全写入

DOCX 和 PDF 都使用与文档保存一致的同目录临时文件策略：先完整生成到 `<目标文件>.tmp`，成功后替换目标文件；生成失败删除临时文件并保留原目标文件。扩展名与所选格式不一致时由后端补齐正确扩展名。

## 错误处理

- 没有活动文档：菜单禁用。
- 保存对话框取消：无状态错误。
- Mermaid 单图失败：该图退化为代码块，其余内容继续导出。
- 图片缺失：插入含路径的占位文本，其余内容继续导出。
- 图片数据损坏、DOCX 打包失败、Typst 编译失败或文件写入失败：导出整体失败，显示具体消息，不覆盖已有文件。
- 导出过程中切换文档：请求使用启动时的不可变快照，生成内容不混入新活动文档。

## 测试与验收

### 自动化测试

- 前端测试菜单顺序、保存对话框过滤器、取消行为、当前内存快照、全部资源收集、Mermaid 中性主题渲染和 Tauri 请求。
- Rust 单元测试 Markdown 到公共块模型的标题、行内样式、列表、表格、图片、附件和 Mermaid 映射。
- Rust 集成测试生成 DOCX/PDF，验证文件签名、非空、目标扩展名、安全替换和失败不覆盖。
- DOCX 结构测试解包并检查 `word/document.xml`、样式、编号、表格、媒体和关系。
- PDF 使用文本提取验证中文、标题、列表和表格内容，并用 Poppler 渲染每一页检查裁切、重叠、缺字、图片和分页。

### 构建门禁

修改完成后运行：

- `npm test`
- `npm run build`
- `cargo test --manifest-path src-tauri/Cargo.toml`
- `cargo check --manifest-path src-tauri/Cargo.toml`
- `npm run tauri -- build`

本机没有 Word 或 LibreOffice，因此 DOCX 首轮验收采用 OOXML 结构、文本和媒体检查；这不能证明 Word 的最终分页视觉。PDF 可使用现有 `pdftoppm` 完成全部页面视觉检查。

## 删减检查

- 前端导出辅助模块：解决当前内存快照、资源和 Mermaid 组装；删除后 `App.vue` 会承担格式准备细节且无法复用测试。
- `ResourceSession.exportResources()`：解决已加载资源不能通过 `newResources()` 导出；删除后重新打开的图片会丢失。
- `MoraEditorHandle.getMermaidDiagrams()`：解决不依赖内部 DOM 获取已渲染图表；删除后 Mermaid 只能退化为源码。
- 公共文档模型：解决两个格式结构一致性；删除后必须双重解析 Markdown。
- DOCX 输出器：直接对应 Word 验收项。
- PDF 输出器：直接对应 PDF 验收项。

未增加插件接口、工厂、注册中心、模板系统、导出设置面板或后台任务队列。只有在单文档导出耗时超过 2 秒且界面明显冻结时，才增加进度对话框或异步任务事件；只有在系统字体覆盖检查失败时，才评估随应用打包开源中文字体。
