# Mora 多文档与多文件夹工作区设计

> 日期：2026-07-30
>
> 状态：已确认，待实施计划

## 1. 背景

Mora 当前只有一份活动文档状态：`content`、`meta`、`currentPath`、资源会话、草稿和脏状态均由 `App.vue` 直接持有。应用已经具备最近打开、本地笔记索引和全文搜索，但不能同时保留多个尚未关闭的文档，也不能把用户选择的多个文件夹作为当前会话资源展示。

本次设计将 Mora 扩展为“单一中央编辑区 + 左侧会话资源管理器”。它不是 VS Code 式通用文件管理器，也不增加顶部标签页。核心目标是让用户同时打开多个 `.mdx`、普通 `.md` 和多个文件夹根目录，在文件间切换时保留各自内容、资源、草稿与本次运行期间的编辑器状态。

## 2. 已确认需求

- 左侧栏只展示当前会话中尚未关闭的独立文件、未命名文档和文件夹根目录。
- 历史文件继续放在“文件 → 最近打开”，不与左侧当前会话混合。
- “最近打开”按规范路径去重，菜单显示最近 10 个，“查看全部”最多保留 50 个不同文件。
- 支持同时打开多个独立文件和多个文件夹根目录。
- 文件夹树显示 `.md`、`.mdx` 及其相关目录。
- 一个文件位于任一已打开文件夹中时，不在“打开的文件”分区重复出现。
- 中央只保留一个活动编辑区域，不增加顶部标签页。
- 文档间切换时不询问保存；每个文档独立保留正文、资源、脏状态、草稿，以及本次运行期间的撤销、光标和滚动状态。
- 重启 Mora 后恢复上次尚未主动关闭的文件、文件夹、活动文档和未保存草稿，但不恢复撤销历史。
- 允许同时存在多个未保存文档，显示为“未命名文档 1、2……”。
- 关闭文件夹时同步关闭其中已经打开的文档；未保存文档依次提示“保存 / 不保存 / 取消”。
- 外部文件变化在 Mora 重新获得焦点时扫描，并提供手动刷新；第一版不做实时文件监听。
- 普通 `.md` 以导入语义打开，不修改原文件；首次保存必须另存为 `.mdx`。
- `.md` 引用的本地图片和附件在另存为 `.mdx` 前提示用户并转换进包内。

## 3. 方案比较

### 3.1 方案 A：单编辑器视图与每文档状态快照

中央只保留一个可见编辑器。Mora 应用层保存每个文档的规范 Markdown、元数据、资源、草稿和文件状态；CodeMirror 与 ProseMirror 使用各自公开的 `EditorState` 切换文档运行时状态。

优点：

- 不为每个文件保留完整编辑器 DOM。
- 能隔离撤销、选择区和滚动状态。
- 继续使用 CodeMirror、ProseMirror/Milkdown 官方状态 API。

风险：Milkdown/Crepe 的 AI、插件和中文输入状态必须通过 PoC 与集成测试验证。

### 3.2 方案 B：每文档保留完整编辑器实例

通过多个 Milkdown/CodeMirror 实例和 Vue `KeepAlive` 保存状态。实现直观，但打开文档数量会直接增加编辑器、插件、DOM 和 Blob URL 占用，后台生命周期也更难控制。

### 3.3 方案 C：只交换 Markdown 文本

文档切换时仅替换 `modelValue`。实现最少，但撤销历史、选择区和滚动位置丢失；默认 `replaceAll` 还可能把跨文档替换写入同一 ProseMirror 撤销历史。

采用方案 A。方案 B 只在官方状态切换无法通过验收时重新评估；方案 C 不满足已确认需求。

## 4. 产品界面

### 4.1 左侧会话资源管理器

左侧栏采用已确认的“分区资源管理器”布局：

1. `打开的文件`：未命名文档，以及不属于任何已打开根目录的独立文件。
2. `打开的文件夹`：多个根目录及其 `.md`、`.mdx` 目录树。

展示规则：

- 文件夹排在文件之前，同级按文件名自然排序。
- 活动文档使用明确高亮。
- 已打开但非活动的文件显示打开标记。
- 未保存文档显示圆点标记。
- 有外部冲突或路径不可用时显示状态标记和可访问文本。
- 打开一个包含已有独立文件的文件夹后，文件移动到对应目录树展示，文档状态不变。

左侧栏可折叠、可拖动调整宽度，并保存折叠状态与宽度。支持键盘上下选择、左右展开或折叠、`Enter` 打开。关闭操作使用明确标注的关闭按钮或应用级“关闭当前文档”命令，不把 `Delete` 键绑定为关闭，避免与删除磁盘文件混淆。

### 4.2 空会话

所有文档关闭后，中央显示空白欢迎页，提供：

- 新建文档。
- 打开文件。
- 打开文件夹。

空会话不会自动创建未命名文档。

### 4.3 功能边界

左侧栏不提供删除、重命名、新建目录、移动或复制文件等磁盘管理能力。现有“笔记库与全文搜索”继续保留；打开文件夹只建立路径树，不自动读取和索引全部正文。

## 5. 最少组件与必要性

### 5.1 `useDocumentSession`

职责：

- 持有打开文档集合、打开顺序和活动文档 ID。
- 管理打开、切换、保存、另存为、关闭和恢复。
- 隔离每个文档的规范正文、元数据、资源会话、草稿、脏状态和冲突状态。

必要性：现有 `App.vue` 的单份文档变量无法表达多个并存文档。删除该模块会直接导致文档切换时状态互相覆盖。

它是唯一实现的 Vue composable，不创建接口、工厂、注册中心或状态库。

### 5.2 `WorkspaceSidebar.vue`

职责：

- 展示两个分区、文件夹树及文档状态。
- 发出选择、展开、刷新和关闭意图。

必要性：左侧栏有独立的树形导航、键盘操作和可访问性边界，不应继续扩大 `App.vue` 模板。组件不访问文件系统，不持有正文。

### 5.3 Rust 文件夹与会话命令

职责：

- 扫描文件夹树。
- 读取普通 Markdown 和检查本地资源。
- 持久化工作区会话。
- 提供文件磁盘版本信息。

必要性：项目规则要求本地文件读写全部在 Rust/Tauri command 中完成。前端不能直接承担这些操作。

### 5.4 编辑器状态缓存

`MoraEditor` 增加稳定的 `documentId`。CodeMirror 使用 `EditorView.setState()`；Milkdown 通过公开的 `editorViewCtx` 取得 ProseMirror 视图，并使用 `EditorView.updateState()`。

原始 `EditorState` 只保存在编辑器组件内部的非响应式 Map 中：

- 不进入 Vue reactive/ref。
- 不写入草稿或会话文件。
- 不跨应用重启恢复。
- 关闭文档时立即释放对应状态。

## 6. 文档模型

应用层文档状态使用一个具体类型，不为单一实现增加抽象接口：

```ts
type OpenDocument = {
    id: string;
    path: string | null;
    sourceKind: "mdx" | "markdown-import" | "untitled";
    importSourcePath: string | null;
    displayName: string;
    content: string;
    meta: MdxMetadata | null;
    dirty: boolean;
    diskRevision: DiskRevision | null;
    conflict: boolean;
};
```

路径规则：

- 已保存文档用规范化绝对路径判重。
- Windows 路径比较忽略大小写。
- 同一路径只能对应一个打开文档；再次打开只激活原状态。
- `.md` 导入文档在首次保存前使用规范化 `importSourcePath` 判重；再次打开同一导入源只激活原状态。
- 未命名文档使用会话 ID 判重。
- 另存为目标已被另一个文档打开时拒绝保存，并定位到已有文档。

编辑视图模式继续作为应用级状态，不为每个文档复制一套 WYSIWYG/源码模式配置。不同文档仍分别缓存对应内核的运行时状态。

## 7. 打开、切换与关闭流程

### 7.1 打开文件

1. Rust 规范化路径并读取文件类型。
2. 已存在同路径文档时直接激活。
3. `.mdx` 执行现有 manifest 与版本校验后创建文档状态。
4. `.md` 读取为 `markdown-import`，保留原始来源路径，标记为未保存导入文档。
5. 用户实际打开文件后才更新最近打开和现有笔记索引；扫描文件夹本身不批量更新历史或索引。

最近打开按规范路径去重。同一路径再次打开只更新时间。文件菜单直接展示最近 10 个，底部“查看全部……”打开可搜索列表；完整历史最多保留 50 个不同文件，超过后移除最久未打开记录。路径暂时不可用时保留记录并标记为不可用，用户可以单独移除或清空历史。

### 7.2 切换文档

1. 将当前编辑器内容同步回活动 `OpenDocument`。
2. 保存当前文档的编辑器运行时状态。
3. 激活目标文档及其资源投影。
4. 使用目标文档的 EditorState；首次激活则从规范 Markdown 创建新状态。

切换不触发保存确认。

### 7.3 关闭文件

- 干净文档直接关闭并释放编辑器与资源状态。
- 未保存文档依次提供：
    - `保存`：成功后关闭。
    - `不保存`：删除该文档草稿并关闭，不删除磁盘文件。
    - `取消`：停止当前关闭操作。
- 保存失败时保留文档和草稿。

### 7.4 关闭文件夹

1. 收集该根目录中所有已打开文档。
2. 按稳定的打开顺序处理未保存文档。
3. 任一文档选择取消或保存失败时，中止整个文件夹关闭流程。
4. 全部处理成功后关闭相关文档并移除根目录。

从 `.md` 导入的文档选择保存时进入 `.mdx` 另存为流程。

## 8. 多文件夹与扫描

支持多个根目录。一个文件位于多个重叠根目录时，以路径最长、最具体的根目录作为唯一展示位置，避免重复。

Rust 扫描规则：

- 递归返回目录与 `.md`、`.mdx` 基础信息，不读取正文或解压归档。
- 跳过符号链接目录、隐藏目录和系统目录。
- 单个根目录最多返回 10,000 个条目；达到上限时停止并返回截断警告。
- 目录不可用时保留根目录记录并显示不可用状态。
- 单个根目录扫描失败不影响其他根目录和已打开文档。

触发扫描：

- 首次打开文件夹。
- 用户手动刷新。
- Mora 窗口从后台重新获得焦点。

## 9. Markdown 导入与本地资源转换

### 9.1 打开语义

普通 `.md` 只作为导入源：

- 原文件不被修改。
- 文档显示原文件名，但状态为未保存。
- 第一次保存必须另存为 `.mdx`。
- 默认保存目录为原 `.md` 所在目录，默认文件名使用原文件名并替换扩展名。

### 9.2 资源检查

另存为前，Rust 检查 Markdown 图片、附件链接和明确的 HTML `src`/`href` 本地引用：

- 相对路径以原 `.md` 目录解析。
- 绝对本地路径按其真实位置读取。
- `http://`、`https://`、`data:`、锚点和其他非本地协议保持原样。
- 只读取普通文件，拒绝目录。
- 使用现有资源大小和总量限制；超限必须显示原因。

确认界面列出：可导入资源、缺失资源、读取失败资源和超限资源。用户可以取消，或继续并保留无法转换的原引用。

### 9.3 转换与命名

- 图片写入 `assets/`。
- 其他本地文件写入 `attachments/`。
- 文件名经过现有安全规范化。
- 同名不同内容使用稳定数字后缀，禁止覆盖。
- 相同源文件被多次引用时只导入一次并统一改写引用。
- 保存请求中的规范 Markdown 只写包内相对路径。

最终归档继续使用现有 `.tmp`、`.bak` 安全保存流程；任何转换失败不得留下半成品正式文件。

## 10. 资源生命周期

每个文档拥有独立资源会话。为了保证 Milkdown/ProseMirror EditorState、撤销历史和图片节点在文档切换后仍有效，文档一旦激活过，其显示用 Blob URL 保留到该文档关闭：

- 规范 Markdown 从不保存 Blob URL。
- 只加载正文实际引用的资源，不预加载归档中的全部附件。
- 文档切换时不撤销其 Blob URL，避免缓存状态和撤销历史引用失效地址。
- 尚未保存的新资源保留原始数据，直到保存、放弃或关闭。
- 新资源继续随草稿持久化，保证异常退出后可恢复。
- 关闭文档时释放全部 Blob URL 和内存资源。

## 11. 外部修改与冲突

`DiskRevision` 至少包含规范路径、修改时间和文件大小。Mora 重新获得焦点时只对已打开文件检查版本；文件夹扫描不读取全部正文。

处理规则：

- 磁盘变化且文档干净：自动重新读取，清空该文档旧撤销历史。
- 磁盘变化且文档未保存：保留双方内容并标记冲突，不自动覆盖。
- 非活动文档只显示冲突标记；切换、保存或关闭时要求处理。

冲突操作：

- `覆盖磁盘版本`：明确确认后，将当前磁盘版本写入现有历史，再保存 Mora 内容。
- `重新加载磁盘版本`：明确确认放弃 Mora 未保存内容后重新读取。
- `另存为`：将 Mora 内容保存到新路径，原磁盘文件不变。

保存失败时保持冲突标记和草稿。

## 12. 会话与草稿持久化

应用数据目录增加版本化 `workspace-session.json`，只保存：

- 独立文件路径与打开顺序。
- 文件夹根目录与顺序。
- 目录展开状态。
- 活动文档 ID 或路径。
- 未命名文档的草稿标识。
- 侧栏折叠状态和宽度。

会话文件不复制正文、资源或原始 EditorState。正文与新资源继续由扩展后的现有草稿机制保存。

会话文件采用同目录临时文件加原子替换。损坏时回退为空会话并显示警告，不阻止应用启动。恢复流程中单个文件失败不阻止其他文件恢复；暂时不可用的移动硬盘或网络目录保持在侧栏中供用户重试或关闭。

## 13. 错误处理与安全

- 所有文件系统访问继续通过 Tauri command。
- `.mdx` 打开仍必须校验 `manifest.json`、版本和加密标志。
- 文件夹扫描不跟随目录符号链接，防止递归循环。
- Markdown 资源转换在读取前规范化路径，并在写入归档时使用安全内部路径。
- 任何关闭流程只有在所有必要保存成功后才删除草稿和会话状态。
- UI 必须区分路径不可用、格式无效、资源缺失、资源超限、外部冲突和保存失败。

### 14.4 桌面验收

## 15. 当前必须、条件升级与本次不实现

### 15.1 当前必须实现

- 多文档会话与左侧分区资源管理器。
- 多根目录扫描与焦点刷新。
- `.md` 导入和本地资源转换。
- 会话/草稿恢复、关闭流程和外部冲突保护。
- CodeMirror 与 Milkdown 官方状态 API 的多文档隔离。

### 15.2 仅在指标不达标时增加

- 实时文件监听：仅当用户明确要求 Mora 保持前台时在一秒内显示外部变化。
- 多编辑器实例：仅当单编辑器状态切换无法通过 Markdown 往返、中文输入、AI、撤销和资源验收。
- 扫描分页或虚拟树：仅当 10,000 条目内的实际渲染或扫描超过可接受交互时间。

### 15.3 本次不实现

- 顶部文档标签页。
- Pinia 或其他第三方状态库。
- 通用工作区接口、EditorAdapter、工厂、注册中心或插件协议。
- 删除、重命名、移动、复制、新建目录等文件管理。
- 文件夹全部正文的自动索引。
- 跨应用重启的撤销历史。
- 超过 50 个文件的无限最近打开历史。

## 16. 删减检查

| 新增内容               | 解决的已确认需求           | 现有能力不能直接承担的原因           | 删除后失败的验收项         |
| ---------------------- | -------------------------- | ------------------------------------ | -------------------------- |
| `useDocumentSession`   | 多个未关闭文档及独立状态   | `App.vue` 只有一份文档状态           | 切换、关闭、草稿和冲突隔离 |
| `WorkspaceSidebar.vue` | 左侧文件/文件夹分区树      | 现有库面板是模态搜索结果，不是会话树 | 多根目录导航与键盘操作     |
| Rust 扫描/会话命令     | 文件夹、普通 `.md`、持久化 | 前端按项目规则不能直接访问磁盘       | 文件夹扫描、恢复和资源转换 |
| 编辑器状态缓存         | 文档独立撤销、光标和滚动   | 当前 `replaceAll` 只替换正文         | 多文档编辑器状态隔离       |

已删除的非必要设计：顶部标签页、状态库、实时监听、通用 WorkspaceAdapter、并行编辑器实现和完整文件管理器。当前方案只保留满足已确认需求所需的四个新增边界。
