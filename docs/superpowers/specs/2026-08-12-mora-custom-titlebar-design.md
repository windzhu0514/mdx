# Mora 一体化自绘标题栏设计

## 目标

用跟随六套主题的一体化标题栏替代 Windows 原生标题栏，让窗口顶部与编辑器整体视觉一致，同时保留桌面软件应有的拖动、最大化、最小化、关闭和未保存保护体验。

## 方案选择

采用单行一体化方案：把现有菜单栏升级为自绘标题栏，不新增第二行。

未采用的方案：

- 标题栏和菜单栏分两行：交互直观，但额外占用垂直编辑空间。
- 仅调整系统标题栏颜色：无法稳定覆盖六套主题，也不能消除系统标题栏与应用菜单栏的割裂。

## 布局

标题栏保持紧凑的单行结构，高度约 `42px`：

```text
┌──────────────────────────────────────────────────────────────────────────┐
│ 图标  文件 编辑 格式 插入 视图 关于 │   文档名 / 拖动区   │ 模式 │ — □ × │
└──────────────────────────────────────────────────────────────────────────┘
```

- 左侧：Mora 应用图标与现有菜单。图标通过 Vite `?url` 直接复用 `src-tauri/icons/icon.ico`，不复制第二份资产。
- 中间：当前文档名和可伸缩空白区域。
- 右侧：现有编辑模式切换，以及最小化、最大化/还原、关闭按钮。
- 窄窗口下优先压缩中间文档名；模式切换沿用当前紧凑布局规则，菜单和窗口控制始终可用。

## 窗口行为

- 在 Tauri 主窗口配置中关闭系统装饰：`decorations: false`。
- 仅中间文档名区域使用 Tauri 官方 `data-tauri-drag-region` 响应窗口拖动，菜单、模式切换和窗口按钮都不属于拖动区。
- 中间区域的双击最大化/还原交给 Tauri 拖动区域内置行为处理，不额外绑定 `dblclick`，避免一次双击触发两次切换。
- 最小化按钮调用 `minimize()`。
- 最大化按钮调用 `toggleMaximize()`，并依据 `isMaximized()` 显示“最大化”或“还原”图标和辅助文本。
- 关闭按钮调用现有 `close()` 流程。现有 `onCloseRequested` 监听继续负责保存进行中拦截和未保存文档确认，不复制第二套关闭逻辑。
- 监听窗口大小变化后刷新最大化状态，避免通过按钮、双击或系统贴靠改变状态时图标失真。

## 组件边界

新增 `WindowControls.vue`，只负责三个窗口按钮、最大化状态和 Tauri 窗口命令。

该组件是必要的，因为：

- 它解决窗口控制这一独立且可测试的职责。
- `App.vue` 已承担文档、菜单、编辑器和关闭保护；继续把平台窗口控制塞入其中会扩大耦合。
- 删除该组件会导致最小化、最大化、还原和关闭按钮验收项失败。

现有 `App.vue` 仍负责标题栏布局与文档标题，并在文档名区域声明官方拖动属性。拖动和双击行为由 Tauri 处理，不需要额外抽象或 composable。

## 权限与配置

在主窗口 capability 中只增加所需权限：

- `core:window:allow-minimize`
- `core:window:allow-toggle-maximize`
- `core:window:allow-start-dragging`（供官方拖动区域使用）

`core:default` 已包含读取最大化状态和拖动区域双击所需的内部切换权限。保留现有 `allow-close` 和 `allow-destroy`，不重复列出现有权限，也不授予设置窗口装饰、任意位置/尺寸或其他无关权限。

## 视觉规则

- 标题栏背景继续使用 `--color-bg-chrome`，自然跟随六套主题。
- 普通窗口按钮使用当前文字和悬停令牌，保持安静、原生桌面感。
- 关闭按钮只在悬停/键盘聚焦时使用 Windows 风格红色背景和白色图标。
- 图标使用内联 SVG，不新增图标依赖；线宽、视觉尺寸和按钮点击区域统一。
- 保留底部分隔线，取消任何会让标题栏显得悬浮卡片化的圆角或外边距。
- 所有按钮提供中文 `aria-label`、`title` 和可见焦点样式。

## 与窗口状态恢复的关系

现有 Rust `window_state` 继续负责窗口位置与普通尺寸恢复。自绘标题栏只调用 Tauri 窗口命令，不写入第二份位置、尺寸或最大化状态，因此不会形成双状态源。

关闭系统装饰会改变窗口外框尺寸，但现有恢复逻辑根据运行时 `outer_size` 与 `inner_size` 计算边框差值，可继续适配无装饰窗口。

## Web 预览与错误处理

- Web 预览环境保留标题栏外观，但窗口按钮不调用 Tauri；按钮应隐藏，避免出现无效控制。
- Tauri 命令失败时不阻断编辑器；组件记录错误并保持当前状态，下次窗口事件重新同步。
- 关闭失败或被现有关闭保护拦截时，窗口保持打开。

## 测试与验收

1. Tauri 配置关闭原生装饰，capability 仅包含所需窗口权限。
2. 六套主题下标题栏使用 `--color-bg-chrome`。
3. 拖动只从文档名区域触发，交互控件不会误拖动窗口。
4. 双击标题区域、最大化按钮均可在最大化与还原之间切换。
5. 最小化按钮有效；最大化图标能随窗口状态变化。
6. 关闭按钮仍经过现有未保存和保存中保护。
7. 760px 最小宽度下菜单、编辑模式和三个窗口按钮保持可操作。
8. Web 测试、主题测试和窗口关闭测试通过。
9. `npm run build`、`cargo check --manifest-path src-tauri/Cargo.toml` 和 `npm run tauri -- build` 均成功。

## 删减检查

当前只新增一个窗口控制组件；标题栏布局继续复用现有菜单栏，关闭保护继续复用现有监听，窗口状态继续复用现有 Rust 实现。不新增状态库、窗口服务、命令适配层、图标依赖或第二套窗口持久化机制。
