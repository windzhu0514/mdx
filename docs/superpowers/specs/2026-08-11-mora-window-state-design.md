# Mora 窗口位置、大小与屏幕适配设计

## 背景

Mora 当前只在 `tauri.conf.json` 中声明固定逻辑尺寸 `1040×760`。在混合 DPI 的多显示器环境中，窗口实际外框可能超过显示器工作区并遮挡任务栏。应用也不会记住用户关闭前的正常窗口位置和大小。

Moji 的参考实现保存窗口的 `getNormalBounds()`，在移动、缩放和关闭时更新持久化状态，并跳过最小化、全屏状态。Mora 使用 Tauri，因此采用 Tauri 官方窗口状态能力，不复制 Electron 事件模型。

## 当前必须实现

1. 保存主窗口最后一次正常状态下的位置和大小。
2. 下次启动时恢复该位置和大小。
3. 恢复后以窗口所在或距离最近的显示器工作区为边界校正窗口：
   - 外框宽高不得超过工作区；
   - 标题栏和边框必须计入尺寸；
   - 窗口必须完整位于工作区内；
   - 负坐标显示器上的有效位置必须保留。
4. 显示器被移除、分辨率变化或 DPI 变化后，失效状态不得导致窗口不可见或超出屏幕。
5. 缺失、损坏或无法读取的状态文件不得阻止应用启动，回退到配置中的默认尺寸。
6. 主窗口在恢复和校正完成前保持隐藏，首次可见时即处于最终位置和大小，不得先在旧显示器闪现再跳转。

## 实现设计

### 状态持久化

使用 Tauri 官方 `tauri-plugin-window-state`，只启用 `POSITION`；窗口客户区大小由 Mora 另存为逻辑像素：

- 插件只负责把物理像素位置写入应用配置目录；
- Mora 把最后一次可见、未最小化、未最大化时的客户区大小换算为逻辑像素，并写入应用配置目录；
- 启动时先恢复位置，再用当前显示器 DPI 把逻辑大小交给 Tauri；禁止把保存的物理宽高跨显示器直接恢复；
- 最小化或最大化时不覆盖正常窗口边界；
- 不恢复可见性、装饰、全屏等与本需求无关的状态。

主窗口跳过插件的自动恢复，由应用启动流程显式恢复。插件 2.4.1 保存的是物理宽高；在 150% 主屏创建窗口、再恢复到 100% 副屏时，尺寸会按错误显示器的 DPI 换算并在每次启动后缩小，因此不能启用插件的 `SIZE`。显式恢复逻辑尺寸后再校正，既避免跨 DPI 累积误差，也避免恢复超过工作区的窗口。

### 工作区校正

新增一个窗口状态模块，包含无副作用的矩形校正函数和平台接入：

1. 读取恢复后的外框位置、外框尺寸和客户区尺寸。
2. Windows 使用系统公开的显示器信息 API 获取最近显示器的工作区，排除任务栏。
3. 用“外框减客户区”计算标题栏和边框占用。
4. 将客户区尺寸限制到工作区扣除窗框后的范围。
5. 将外框位置限制在工作区内；仅当原状态越界时移动窗口。
6. 若 Windows 工作区查询失败，回退到 Tauri 当前显示器的完整物理范围，继续启动。

窗口位置插件、逻辑尺寸状态和工作区校正缺一不可：三者分别解决位置持久化、跨 DPI 尺寸稳定和任务栏/屏幕边界越界。

### 启动顺序

1. Tauri 以 `visible: false` 创建主窗口。
2. 恢复保存的位置，并应用保存的逻辑客户区尺寸；状态缺失或损坏时使用 `1040×760`。
3. 校正到有效显示器工作区。
4. 显式显示并聚焦主窗口；显示或聚焦失败仅记录诊断。
5. 进入现有应用运行流程。

首次启动没有保存状态时，同样校正配置中的默认尺寸，因此当前超屏问题会立即消失。

## 错误处理

- 状态文件缺失或损坏：忽略并使用默认状态。
- 保存失败：不阻止关闭，下次使用最后一次成功状态或默认状态。
- 保存的显示器不存在：不应用失效位置，由系统选择显示器后再校正。
- 工作区查询失败：回退到显示器完整范围，不让应用启动失败。

## 测试

先为纯矩形校正函数编写失败测试，再实现：

- 超大窗口缩小到工作区并计入窗框；
- 左、上、右、下越界位置被拉回；
- 位于负坐标副屏的有效窗口保持不变；
- 已在工作区内的正常窗口尺寸和位置保持不变；
- 工作区小于期望尺寸时不产生负数或零尺寸。
- 物理尺寸按 DPI 换算后得到稳定的逻辑尺寸；窗口插件不得再包含 `SIZE`。

随后运行 Rust 定向测试、完整前端构建、`cargo check` 和 Tauri 打包。

配置回归测试必须验证 `main` 窗口为 `visible: false`；真实冷启动验收记录 Mora 主窗口第一次可见时的外框，确认没有后续位置或尺寸跳变。

## 本次不实现

- 不持续强制限制用户拖动或缩放窗口；校正在启动恢复阶段执行。
- 不保存最小化、最大化、全屏或可见性状态。
- 不增加设置页或窗口尺寸选项。
- 不修改编辑器布局和 `.mdx` 文件格式。

## 删减检查

- `tauri-plugin-window-state`：只承担位置持久化；删除后无法记住关闭前的位置。
- 窗口状态模块：承担逻辑尺寸持久化、跨 DPI 换算、工作区校正与可测试几何逻辑；删除后会再次出现尺寸逐次缩小或窗口越界。
- Windows 显示器工作区 API：用于排除任务栏；仅使用 Tauri 的显示器完整尺寸会保留当前遮挡任务栏的问题。

没有新增接口、工厂或注册中心；仅增加一个必要的逻辑尺寸状态文件，避免复用插件物理尺寸造成跨 DPI 累积误差。
