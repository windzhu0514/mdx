# Mora 文档命名与编辑区布局设计

> 日期：2026-07-30
>
> 状态：已确认，待实施计划

## 1. 背景

Mora 当前在编辑区顶部提供一个大号标题输入框，并在其下方提供标签编辑器。两者持续占用正文空间。应用顶部同时存在 Windows 原生标题栏和 Mora 完整菜单栏。

本次调整的目标是扩大编辑区域，并将文档名称与实际 `.mdx` 文件名保持一致，同时保留桌面应用已有的菜单发现性和窗口操作能力。

## 2. 已确认需求

- 保留 Windows 原生标题栏。
- 保留现有完整菜单栏，不改为单个紧凑菜单按钮。
- 删除编辑区上方的大号标题输入框。
- 删除标签编辑 UI。
- 文档名称不允许在界面中直接输入。
- 新建且尚未保存的文档显示为 `未命名文档`。
- 保存后的文档名称由用户在保存对话框中选择的 `.mdx` 文件名决定。
- 已保存文档始终以文件名去掉 `.mdx` 扩展名后的结果作为显示名称。
- 旧文件中的标签数据继续保留，不因删除标签编辑 UI 而丢失。
- PDF 正文标题仅来自 Markdown 正文，不额外插入元数据标题。

## 3. 方案比较

### 方案 A：保留大标题输入框

优点是标题编辑最直接，缺点是与“文件名就是文档名”的规则冲突，并继续占用大量正文空间。

### 方案 B：通过文件菜单弹窗修改标题

可以删除大标题输入框，但会重新引入文件名与包内标题不一致的问题，也增加一个没有必要的标题编辑流程。

### 方案 C：文件名作为唯一可见文档名

删除标题输入框，保存时由用户通过文件名命名文档。菜单栏显示只读名称，包内 `meta.title` 作为兼容字段随保存同步。

采用方案 C。它最符合已确认需求，不需要新组件、新接口或新的状态层。

## 4. 界面设计

### 4.1 顶部区域

Windows 原生标题栏保持不变。Mora 菜单栏保留完整菜单，并调整为三个区域：

1. 左侧：`文件 / 编辑 / 格式 / 插入 / 视图 / 关于`。
2. 中间：只读文档名称。
3. 右侧：`所见即所得 / 仅源码 / 垂直双栏`模式切换。

文档名称不使用输入框。名称过长时使用单行省略，悬停时通过原生提示显示完整名称。

窄窗口下优先隐藏已有的紧凑模式切换区域，为完整菜单和文档名称保留空间；所有模式仍可从“视图”菜单进入。

### 4.2 编辑区域

删除大号标题输入区和标签编辑区，编辑器直接占用原来由这两个区域释放的空间。

移除标签编辑入口不等于删除标签数据。打开、保存、历史恢复和 Markdown 导入仍原样携带 `meta.tags`。

## 5. 文档命名规则

### 5.1 新建

新建文档在尚未保存时显示 `未命名文档`。窗口标题为：

```text
未命名文档 - Mora
```

产生未保存修改后，继续使用现有脏状态标记：

```text
* 未命名文档 - Mora
```

### 5.2 首次保存

首次保存必须由用户在保存对话框中选择路径和文件名。若选择：

```text
D:\Notes\项目计划.mdx
```

则文档名称为 `项目计划`。

保存请求中的顶层 `title` 和 `meta.title` 都使用这个名称。只有保存成功后，当前路径和界面名称才更新。

### 5.3 打开已有文档

打开已有 `.mdx` 时，显示名称始终从实际文件路径推导。即使包内旧 `meta.title` 与文件名不同，界面仍以文件名为准。

旧 `meta.title` 不会仅因打开文件而触发写盘。用户下次成功保存时，`meta.title` 才同步为文件名。

### 5.4 保存与另存为

- 普通保存：从当前路径重新推导名称并写入保存请求。
- 另存为：从用户新选择的路径推导候选名称。
- 取消保存：名称和路径保持不变。
- 保存失败：名称和路径保持不变。
- 另存为成功：名称、路径、最近文件记录和搜索索引使用新文件名。

文件名解析同时支持 Windows `\` 和通用 `/` 路径分隔符。只有末尾 `.mdx` 扩展名被移除，比较时不区分大小写。

## 6. 数据流

现有前端 `title` 状态继续保留，但改为程序控制状态，原因如下：

- `.mdx` 保存请求仍需要 `title`。
- `meta.json.title` 仍属于现有格式。
- 历史记录、最近文件和搜索索引依赖标题字段。
- 窗口标题和菜单栏文档名称需要统一数据源。

不新增标题仓库、适配器或命名服务。文件名提取使用一个纯函数，以便独立测试并供打开、保存和另存为路径复用。

保存时先计算候选标题并构造请求，不提前修改当前 `title`。Tauri command 成功返回后再通过现有笔记应用流程更新界面状态，从而保证失败原子性。

Rust command 和 `.mdx` 文件结构不需要改变。

## 7. PDF 与打印

删除大标题输入区后，不增加打印专用的元数据标题。PDF 中是否存在标题完全由 Markdown 正文决定，例如正文中的一级标题：

```markdown
# 项目计划
```

打印前继续将当前文档名称写入 `document.title`。在系统打印功能允许的情况下，“另存为 PDF”使用该名称作为建议文件名；最终文件名仍由系统打印对话框控制。

## 8. 错误处理

- 无法从路径取得有效文件名时，回退为 `未命名文档`。
- 保存对话框取消不显示错误，也不改变当前状态。
- 保存 command 失败时保留旧路径、旧名称和脏状态，并继续使用现有错误提示。
- 打开失败时不应用候选文件名。
- 删除标签编辑 UI 后，现有标签数据不得被清空或重建。

## 9. 测试与验收

### 9.1 单元与组件测试

- Windows 和 `/` 路径都能正确提取文档名称。
- `.mdx` 扩展名大小写不影响提取。
- 新建文档显示 `未命名文档`。
- 页面中不存在标题输入框和标签编辑器。
- 完整菜单和三种模式入口仍存在。
- 菜单栏显示只读文档名称，并支持长名称省略提示。

### 9.2 集成测试

- 打开文件时，文件名覆盖不一致的旧 `meta.title` 作为界面名称。
- 普通保存会使用当前文件名同步 `title` 和 `meta.title`。
- 另存为成功后切换为新文件名。
- 取消或失败的另存为不会提前改变名称。
- 旧 `meta.tags` 在打开、保存和历史恢复后保持不变。
- 打印不会额外注入标题，且打印期间 `document.title` 使用当前文档名称。

## 12. 删减检查

本设计不新增组件、接口、适配层、状态库、Rust command 或第三方依赖。

唯一新增的逻辑单元是文件路径到文档名称的纯函数。若删除它，打开、保存和另存为会各自重复路径解析，且无法统一覆盖 Windows 路径和扩展名边界测试，因此保留是必要的。
