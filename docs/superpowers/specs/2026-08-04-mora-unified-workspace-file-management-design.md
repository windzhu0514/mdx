# Mora 统一工作空间文件管理设计

## 目标

移除编辑区上方的多标签栏，将左侧工作空间作为文档切换、关闭和文件夹浏览的唯一入口，同时保留现有多文档会话能力。

## 界面结构

工作空间分为两个固定区域：

1. **已打开文件**：列出当前会话中的全部文档，包括文件夹内文件、文件夹外文件、Markdown 导入文档和未命名文档。
2. **文件夹**：保留现有文件夹根节点、目录层级、刷新、关闭和展开行为。

示意：

```text
工作区
  已打开文件
    未命名文档   未保存  ×
    note.mdx             ×
  文件夹
    posts                ↻ ×
      markdown.md
      ...
```

“已打开文件”始终显示。没有打开文档时显示紧凑空状态，不隐藏“打开文件夹”入口。文件夹内已打开的文件允许同时出现在“已打开文件”和文件夹树中：前者负责会话管理，后者负责磁盘位置浏览。

## 交互规则

- 点击“已打开文件”中的文档：激活该文档并更新编辑器内容。
- 点击已打开文档右侧关闭按钮：调用现有文档关闭流程；未保存文档继续显示保存、放弃、取消选择。
- 点击文件夹树中的文件：未打开时打开，已打开时激活。
- 活动文档在“已打开文件”和文件夹树对应位置同时高亮。
- 文档状态继续显示“未保存”“外部更改”“不可用”。
- 新建文档、打开文件、导入 Markdown 和会话恢复后，文档立即出现在“已打开文件”中。
- 关闭文件夹时，仍由现有会话逻辑处理该文件夹所属的已打开文档；文件夹外文档不受影响。
- 键盘导航覆盖两个区域，保持单一树形导航顺序；文档支持 Enter/Space 激活，关闭按钮保持可聚焦和可读标签。
- 关闭文档被取消时，焦点保留在原文档行；关闭成功后，焦点移动到会话自动选中的下一活动文档行；没有剩余文档时，焦点移动到首个文件夹根节点或“打开文件夹”按钮。

## 组件与状态

### 当前必须实现

- 扩展 `WorkspaceSidebar.vue`，在现有文件夹行之前生成已打开文档行。
- 为已打开文档行增加激活与关闭事件；复用现有 `documents`、`activeDocumentId` 和状态标签，不新增正文或会话状态。
- `App.vue` 移除 `DocumentTabs` 的导入、渲染、引用和标签焦点逻辑，将文档关闭后的焦点交还工作空间。
- 删除不再使用的 `DocumentTabs.vue`、对应测试以及仅服务于标签栏的样式。
- 保留 `useDocumentSession` 作为唯一多文档状态来源，不改变 `.mdx` 格式和保存流程。

### 仅在指标不达标时增加

- 当打开文档数量导致侧栏难以浏览时，再增加“已打开文件”区域折叠能力。当前版本保持固定展开，避免隐藏唯一的文档切换入口。

### 本次不实现

- 拖拽排序、固定文档、最近关闭文档。
- 文件移动、重命名、删除和右键菜单。
- 搜索、标签、收藏或新的文件管理状态库。

## 数据流

1. `useDocumentSession` 更新 `documents` 或 `activeDocumentId`。
2. `App.vue` 将同一状态传给 `WorkspaceSidebar` 和编辑器。
3. `WorkspaceSidebar` 根据 `documents` 生成“已打开文件”行，根据 `folders` 生成文件夹树行。
4. 文档行发出 `activate` 或 `close-document`；`App.vue` 调用现有 `activateDocument` 或 `closeDocument`。
5. 会话变更反向驱动工作空间高亮、状态标签和编辑器内容。

该流程没有第二份文档状态，也不复制保存、关闭或冲突处理逻辑。

## 错误处理

- 文档关闭失败时沿用现有错误提示，文档行继续保留。
- 保存中的文档继续阻止关闭，并保持当前焦点。
- 文件夹刷新或关闭失败不移除文件夹树。
- 工作空间只负责发出用户意图，不自行修改文档、草稿或持久化数据。

## 测试与验收

- 工作空间按会话顺序显示全部打开文档，覆盖未命名、MDX、Markdown 导入和文件夹外文件。
- 点击打开文档行可以切换活动文档；活动状态在打开列表和文件夹树同步。
- 点击文档关闭按钮触发现有关闭流程，取消时保留文档，成功时移除文档行。
- 文件夹树仍能打开、激活、刷新、关闭和展开。
- 编辑区不再渲染多标签栏，仍能同时维护多个文档状态。
- 键盘导航和无障碍名称覆盖新增行和关闭按钮。
- 完成后运行全量测试、前端构建、Rust 检查和 Tauri 正式打包。

## 删减检查

- 不新增组件：现有 `WorkspaceSidebar` 已承担工作空间展示，能够直接容纳已打开文档区域。
- 不新增 composable、接口、工厂或状态库：现有会话状态已满足全部验收项。
- 删除 `DocumentTabs`：其唯一职责被工作空间接管，继续保留会造成两个文档入口。
- 保留文件夹树与会话层：分别满足磁盘浏览和多文档状态需求，删除任一都会导致验收项失败。
