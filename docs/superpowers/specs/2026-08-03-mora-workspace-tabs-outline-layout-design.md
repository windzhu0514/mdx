# Mora 工作区、多标签与目录布局设计

> 日期：2026-08-03
>
> 状态：已确认，待用户审阅

## 1. 背景与设计关系

Mora 已完成多文档会话、多个工作区根目录、文档状态隔离、会话恢复、关闭保护和外部冲突处理。当前界面仍使用“左侧工作区 + 左侧目录 + 中央编辑器”的布局，并由工作区侧栏中的“打开的文件”分区承担部分文档切换职责。

本设计是对 `2026-07-30-mora-multi-document-workspace-design.md` 的界面修订，仅替换以下旧结论：

- “中央不增加顶部标签页”。
- 左侧栏默认显示“打开的文件”分区。
- 工作区和本文目录同时位于编辑器左侧。

既有文档会话、草稿、资源、保存、关闭、冲突、Markdown 导入和文件夹扫描语义保持不变。本次不重新设计底层文档模型。

## 2. 已确认目标

- 左侧固定为工作区所在位置，右侧固定为当前文档目录所在位置；“固定”表示空间归属稳定，两侧仍允许收起。
- 中间编辑区顶部增加多文档标签页，作为已打开文档的唯一主要切换入口。
- 打开文件夹后自动显示左侧工作区。
- 当前文档存在 Markdown 标题（H1–H6）时，桌面宽窗口下默认显示右侧目录。
- 编辑器底栏最左端放置工作区显隐按钮，最右端放置目录显隐按钮。
- 两个按钮使用方向相反的镜像图标，不集中放在右侧。
- 编辑器模式切换按钮本次不调整。
- `980px` 作为宽窗口与窄窗口的分界，延续现有工作区紧凑模式阈值。

## 3. 总体布局

宽度大于 `980px` 时，主界面从左到右为：

```text
┌─────────────────────────────────────────────────────────────┐
│                         现有菜单栏                          │
├──────────────┬───────────────────────────┬──────────────────┤
│ 左侧工作区   │ 多文档标签页              │ 右侧本文目录     │
│              ├───────────────────────────┤                  │
│ 文件夹树     │                           │ 当前文档 H1–H6  │
│              │        编辑器             │                  │
│              │                           │                  │
├──────────────┴───────────────────────────┴──────────────────┤
│ [工作区按钮] 状态、路径……              模式、字数 [目录按钮]│
└─────────────────────────────────────────────────────────────┘
```

菜单栏继续覆盖应用全宽。标签页只覆盖中央编辑区域，不延伸到左右侧栏上方。底栏继续覆盖应用全宽，使两个侧栏按钮能够分别贴近应用左右边缘。

## 4. 左侧工作区

### 4.1 展示内容

左侧工作区只展示已打开的文件夹根目录及其 `.md`、`.markdown`、`.mdx` 文件树。移除现有“打开的文件”分区，避免与顶部标签页重复展示同一批文档。

不属于任何工作区文件夹的独立文件、未命名文档和 Markdown 导入文档只出现在标签页中。工作区没有任何文件夹时，侧栏显示简洁空态和“打开文件夹”入口，不恢复“打开的文件”列表。

工作区仍保留现有能力：

- 多个根目录与重叠根目录归属规则。
- 展开、折叠、刷新和关闭文件夹。
- 活动文件、未保存、外部冲突和路径不可用状态。
- 键盘树导航和可拖动宽度。

它仍不是通用文件管理器，不增加删除、重命名、移动、复制或新建目录。

### 4.2 显隐规则

- 用户成功打开文件夹后，工作区自动显示。
- 会话恢复时沿用已持久化的宽度和显隐偏好，不因恢复文件夹而强制覆盖用户偏好。
- 用户手动收起后，切换文档或刷新文件夹不会再次强制展开。
- 底栏最左侧按钮始终存在，用于显示或隐藏工作区。

## 5. 多文档标签页

### 5.1 基本行为

- 每个 `OpenDocument` 对应一个普通固定标签页，不增加临时预览标签。
- 单击工作区文件直接打开普通标签并激活。
- 再次打开相同规范路径时只激活已有标签，不创建重复标签。
- 新建文档、独立打开的文件、工作区文件和 Markdown 导入文档使用同一种标签模型。
- 标签显示文档名、未保存状态和关闭按钮；活动标签有明确视觉高亮。
- 关闭标签继续调用现有文档关闭流程；未保存文档仍使用“保存 / 不保存 / 取消”保护。
- 切换标签只激活文档，不触发保存提示，并继续恢复该文档的撤销、光标、滚动和资源状态。

### 5.2 顺序与溢出

- 标签顺序使用现有文档打开顺序。
- 新标签追加到现有标签末尾，直接沿用当前文档集合的打开顺序；本次不增加额外排序状态或拖拽排序。
- 标签始终保持单行，不换行。
- 空间不足时标签容器横向滚动，不持续压缩成无法辨认的极窄标签。
- 活动标签变化后必须自动滚入可见区域。
- 鼠标滚轮位于标签栏上时可转换为横向滚动；键盘焦点和关闭按钮必须保持可访问。

本次不实现标签固定、标签组、临时预览标签、拆分编辑器和批量标签上下文菜单。

## 6. 右侧本文目录

目录只表示活动文档内部结构，数据继续从规范 Markdown 的 H1–H6 提取，不创建第二份正文或独立渲染器。

### 6.1 桌面宽窗口

- 当前文档存在至少一个 Markdown 标题且用户未手动收起目录时，目录显示在右侧。
- 当前文档没有标题时不占用右侧空间。
- 用户手动收起目录后，切换文档不会强制重新展开。
- 用户手动重新打开后，后续有标题的文档继续显示目录。
- 没有活动文档或当前文档没有标题时，底栏右侧按钮保持可见但禁用，并通过提示说明“当前文档没有目录”。

现有目录点击跳转、层级缩进和可访问名称保持不变。目录侧栏保持固定宽度并支持收起，本次不增加独立宽度偏好、目录搜索、拖动标题或标题编辑。

### 6.2 手动偏好

现有 `showToc` 继续表示用户显隐偏好，标题是否存在只决定目录能否实际展示。文档没有标题时不应把用户偏好改写为关闭；这样切换回有标题文档时仍能恢复用户原来的选择。

## 7. 底栏按钮

现有 `StatusBar` 两端增加两个图标按钮：

- 最左端：工作区按钮，图标突出窗口左侧窄栏。
- 最右端：目录按钮，图标突出窗口右侧窄栏。

按钮规则：

- 图标方向与目标侧栏一致，不复用完全相同的图形。
- 面板可见时使用激活样式，不可见时使用普通样式。
- 提供明确的 `aria-label`、`title` 和展开状态，不只依赖颜色表达状态。
- 两个按钮始终占据底栏外侧位置；现有状态、路径、保存状态、模式和字数位于两者之间。
- 右侧按钮在当前文档无标题时禁用；左侧按钮始终可用。

把两个按钮都放在右侧的方案不采用，因为它使左侧工作区入口远离目标面板，并增加两个相似图标的辨认成本。

## 8. `980px` 窄窗口规则

“窄窗口”只指 Mora 应用窗口宽度不超过 `980px`，与显示器分辨率和正文阅读宽度无关。

窄窗口下：

- 右侧目录默认不自动展开，用户可从底栏右侧按钮主动打开。
- 左侧工作区和右侧目录以覆盖编辑器的浮层方式显示，不继续挤压正文宽度。
- 同一时间只显示一个覆盖侧栏；打开另一侧时关闭当前覆盖侧栏。
- 用户点击文件、目录条目或编辑区域后，覆盖侧栏可以收起，但不得丢失工作区展开状态或目录显隐偏好。
- 响应式收起只改变当前窄窗口的实际展示，不覆盖宽窗口下持久化的用户偏好。
- 底栏左右按钮始终显示。

窗口重新变宽后，恢复宽窗口下的工作区和目录偏好。

## 9. 最少组件与数据流

### 9.1 新增 `DocumentTabs.vue`

职责仅限：

- 根据 `documents` 和 `activeDocumentId` 渲染标签。
- 发出激活和关闭意图。
- 管理活动标签滚入可见区域与标签栏横向滚动。
- 提供标签列表、标签项和关闭按钮的键盘/可访问性语义。

它不持有正文、脏状态或文档生命周期，不访问 Tauri。删除该能力会导致“通过顶部标签切换多个已打开文档”和“溢出时仍可访问活动标签”验收失败。

### 9.2 复用现有组件

- `useDocumentSession` 继续作为打开文档、活动文档和关闭流程的唯一来源，不新增状态库。
- `WorkspaceSidebar.vue` 移除独立文件分区，继续负责文件夹树。
- `TableOfContents.vue` 移到编辑器右侧，并增加与窄窗口覆盖层一致的外观和显隐接线。
- `StatusBar.vue` 增加两个按钮所需的状态属性和事件，不新增独立布局控制组件。
- `App.vue` 只负责编排三栏、把标签事件接到现有 session，并协调宽/窄窗口显示。

### 9.3 数据流

```text
工作区文件点击 ──> session.openPath / activate
                         │
session.documents ───────┼──> DocumentTabs
session.activeDocumentId ┼──> 活动标签与 MoraEditor
                         └──> 当前文件树状态

活动文档 canonical Markdown ──> H1–H6 提取 ──> 右侧目录

底栏左按钮 ──> 工作区显隐
底栏右按钮 ──> 目录用户偏好
```

规范 Markdown 仍只有现有活动文档投影这一份。标签页、文件树和目录都不复制正文状态。

## 10. 错误处理与状态边界

- 标签关闭、关闭文件夹和窗口关闭继续复用现有保存队列，不创建新的确认状态机。
- 文件夹扫描错误和不可用路径继续在工作区树显示，不影响其他标签和活动文档。
- 目录为空不是错误，只禁用右侧目录按钮并隐藏侧栏。
- 标签切换失败不得改变活动文档；重复路径继续由 session 判重。
- 响应式布局只改变展示，不关闭文档、文件夹或资源会话。
- 侧栏显隐不得触发编辑器内容替换、重建正文状态或取消未完成保存。

## 11. 测试与验收

### 11.1 标签页

- 打开两个文件生成两个普通标签，切换不触发保存提示。
- 重复打开同一路径只激活原标签。
- 独立文件、未命名文档和工作区文件均出现在标签页。
- 未保存标记、活动状态和关闭按钮与文档状态一致。
- 关闭未保存标签继续执行现有三分支保护。
- 标签溢出保持单行横向滚动，活动标签自动滚入视野。
- 切换标签后正文、撤销、光标、滚动、AI 取消和 Blob URL 生命周期保持既有隔离。

### 11.2 左右侧栏

- 打开文件夹后宽窗口自动显示工作区。
- 左栏只显示文件夹树，不重复显示已打开文档列表。
- 有 H1–H6 时宽窗口显示目录；无标题时隐藏目录并禁用右按钮。
- 手动收起后切换文档不强制重新展开。
- 底栏最左和最右按钮分别控制对应侧栏，并具有正确可访问状态。

### 11.3 响应式

- `981px` 及以上使用三栏布局。
- `980px` 及以下侧栏使用覆盖层，不压缩中央编辑区。
- 窄窗口只允许一个覆盖侧栏显示。
- 窄窗口与宽窗口切换不覆盖用户持久化偏好。
- 最小 `760px` 窗口下仍可访问标签、编辑器和两个侧栏按钮。

完成代码修改后按仓库要求运行：

```bash
npm run build
cargo check --manifest-path src-tauri/Cargo.toml
npm run tauri -- build
```

与相关组件已有测试共同运行前端测试；若修改 Rust 代码，则同时运行对应 Rust 测试。本设计预计不需要修改 Rust。

## 12. 当前必须、条件升级与本次不实现

### 12.1 当前必须实现

- 左工作区、中间标签与右目录的三段式布局。
- 普通固定标签、判重激活、关闭、脏标记和单行溢出滚动。
- 底栏两端的侧栏显隐按钮。
- 打开文件夹与有标题文档的默认显示规则。
- `980px` 窄窗口覆盖层行为。

### 12.2 仅在指标不达标时增加

- 标签下拉总览：仅当实际使用中横向滚动无法可靠定位大量标签。
- 标签虚拟化：仅当大量打开文档导致标签渲染出现可测量卡顿。
- 独立侧栏状态模块：仅当 `App.vue` 的宽/窄窗口协调无法通过竞态和恢复测试。

### 12.3 本次不实现

- 编辑器模式切换按钮重排。
- 临时预览标签、标签固定、拖拽排序、标签组和拆分编辑器。
- 通用文件管理器能力。
- 新状态库、WorkspaceAdapter、标签注册中心或插件协议。
- Rust 文件格式、文件夹扫描和会话模型改造。

## 13. 删减检查

| 新增或修改边界 | 解决的已确认需求 | 现有组件为何不能直接承担 | 删除后失败的验收项 |
| --- | --- | --- | --- |
| `DocumentTabs.vue` | 多文档标签切换与溢出 | 现有界面没有标签语义或横向滚动边界 | 标签切换、关闭和溢出访问 |
| `WorkspaceSidebar.vue` 精简 | 工作区只承担文件夹导航 | 当前“打开的文件”会与新标签重复 | 左栏职责单一与去重展示 |
| `TableOfContents.vue` 右移与紧凑态 | 当前文档右侧导航 | 当前组件位于工作区与编辑器之间，窄屏无右侧覆盖行为 | 右侧目录与 `980px` 验收 |
| `StatusBar.vue` 两端按钮 | 可恢复左右侧栏 | 当前底栏没有侧栏控制入口 | 收起后的恢复与空间映射 |

已删除的非必要方案：文件/目录共用标签侧栏、两列左侧栏、上下分区侧栏、临时预览标签、标签状态库、编辑器模式按钮重排，以及两个侧栏按钮集中到右侧。
